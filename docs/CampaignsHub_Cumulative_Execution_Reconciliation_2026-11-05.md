### P0-B — أقفل ما بدأ، قبل فتح مسارات تجميلية جديدة
- **مركز التكاملات — لا يُنسى:** `feat/integrations-center-2` و`feat/integrations-center-clean` و`feat/integrations-projects-estate` و`fix/integrations-sources-removal` فروع قائمة. قارن نطاقها ثم أنجز واجهة عربية RTL Project-First بثلاثة أقسام **المشاريع / المصادر المرتبطة / التدقيق**، مع اختيار مشروع → مزود → تفويض → اكتشاف → اختيار مورد → تأكيد الربط → تحقق → مزامنة. يعرض حالات مستقلة للتفويض والربط والمزامنة والحداثة والخطأ، ويدعم بحث/فرز/فصل/إعادة تفويض وتظهر هوية *حساب المنصة* لا بريد مساحة CampaignsHub. لا تُعتبر الموارد المكتشفة مرتبطة ولا تُزامَن تلقائيًا.
- **Unified Integration Core:** استكمل مراحل العقد 16 دون هندسة موازية: Registry/Capabilities، Credential Lifecycle، Resource Binding، Cursor/Checkpoints، Webhook Verification/Replay، Idempotency/Rate limits/Recovery، Gradual Migration. فحص حدود الاختبارات الذي بدأ لا يمثل انتهاء المراحل C–G. افصل تكاملات تنتظر Credentials عن مهام البرمجة.
- **Duplicate تقارير:** `fix/report-duplicate-draft` يجب أن يفتح محرر مسودة مستقلة قابلًا لتعديل المصادر والأقسام والمعاينة ثم الحفظ/النشر؛ لا رابط قبل فعل مشاركة مستقل؛ لا يتأثر الأصل؛ يجب استكمال تفضيلات الرابط واختبارات الجوال/PDF.
- **Snapshot Versions:** فرع سجل النسخ السابقة/استرجاعها، مع منع الكتابة على النسخة المحفوظة بصمت.
- **تسريع التقارير/المزامنة:** `perf/sync-isolation-2` وما بعده لتخفيف بطء :31، وإتاحة أحدث تقرير مكتمل مع إظهار تحديث الخلفية دون إيهام بتحديث فوري.

## 5. سياسة عمل مستمر بلا نسيان ولا فروع متنافسة
1. `git fetch origin` ثم اقرأ `CLAUDE.md` و`REQUIREMENTS_TRACEABILITY_MATRIX.md` و`RESUME_STATE.md` و`OWNER_OBSERVED_DEFECTS.md` وقائمة PRs/CI/Lander/Worktrees. لا تستخدم worktree مملوكًا لجلسة أخرى.
2. أنشئ **خريطة توفيق داخل المصفوفة نفسها** لكل بند سابق من ملفات MD: status / branch / acceptance evidence / blocker. سدّ أي صف ناقص ثم توقف عن إجراء جرد متكرر.
3. **أغلق الفروع الجاهزة أولًا** بترتيب المخاطر: الأمان → المال → العزل/التكاملات → الفلاتر وDuplicate → Smart Code والبريد/التحقق → UI تكاملات وGA4 وسائر التطوير. عدل الترتيب فقط لدليل حاسم على خطر أعلى أو تبعية تقنية، مع تسجيل السبب.
4. قسم مهام الوكلاء المستقلة إلى worktrees آمنة، لكن لا تجعل وكلاء متوازيين يعدلون الملفات نفسها؛ Lander واحد للدمج مع CI كامل وDeploy تدريجي. لا تحذف فروعًا ولا تتخطّ أي حماية دون تفويض.
5. بعد كل PR: اختبارات fail-first حيث ينطبق → unit/integration/E2E/security → CI أخضر → merge → deploy → smoke/functional/production evidence → تحديث المصفوفة وسجل العيوب والحالة. لا تجعل فشلًا متكررًا في WebKit يُعاد إلى ما لا نهاية: حقق في سبب flake وموارد CI بدل إعادة تشغيل عمياء.
6. إذا احتاج بند Credentials أو موافقة مالية/أمنية/ترحيل إنتاجي مؤثر: صنفه `BLOCKED_EXTERNAL_CREDENTIALS` أو `BLOCKED_OPERATIONAL_EVIDENCE` مع إجراء مالك محدد؛ **واصل كل البقية**. لا تخلق حسابات إنتاجية أو تعرض أسرارًا أو تغيّر بيانات حية دون تفويض.
7. حافظ على الحالات الحقيقية: `VERIFIED_LIVE`، `PARTIAL`، `IMPLEMENTED_NOT_VERIFIED`، `DEMO`، `AWAITING_CREDENTIALS`، `BLOCKED_EXTERNAL_CREDENTIALS`، `BLOCKED_OPERATIONAL_EVIDENCE`، `NOT_IMPLEMENTED`.
8. خلال التنفيذ أرسل تحديثات **بعد إنجاز ملموس** فقط، لا رسائل «المراقب يعمل» المتكررة؛ ألخص: ما تغير على main، اختبار ناجح، نشر، إثبات حي، التالي، العوائق الحقيقية. لا تعد بأن GitHub سيُشغّل Claude تلقائيًا؛ تشغيل الوكلاء يحتاج بيئة تنفيذ نشطة.

## 6. معيار إنهاء التكليف الشامل
لا يكفي أن يُدمج آخر طلب أو ينتهي فرع واحد. يكون العمل المنجز فقط عندما تتحقق معايير قبول كل متطلب سابق ذات صلة في المصفوفة وتغلق الفجوات مع أدلة، أو يسجل العائق الخارجي غير القابل للتنفيذ بدقة دون اعتباره منجزًا. ولا يمكن وعد «100% دون أخطاء» دون اختبارات واقعية؛ المطلوب أقل مخاطرة وقياس وتوثيق دقيق.
